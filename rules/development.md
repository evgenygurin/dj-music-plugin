# Правила разработки

## Инструменты

- Используй `uv` для установки зависимостей и запуска проектных инструментов.
- Используй существующие Make/validation commands проекта вместо самодельных эквивалентов.

## Проверки

- Перед коммитом выполняй релевантные lint, type, architecture и test checks.
- `make check` является агрегированным quality gate, когда изменение должно пройти полный repository gate.
- Не считай исторические результаты из документации доказательством текущего состояния; доказательством является свежий запуск проверки.

## Структура

- Следуй существующим bounded-context и layer boundaries.
- Не создавай корневые файлы только ради удобства локальной реализации.
- Не дублируй существующий контракт в новом параллельном abstraction layer без архитектурной причины.

## Тесты

- Добавляй или обновляй тесты для поведенческого изменения.
- Предпочитай тесты, проверяющие контракт, а не конкретную текущую реализацию.
- Значения вроде общего числа тестов и coverage не фиксируй в постоянной документации: они должны проверяться инструментами.
