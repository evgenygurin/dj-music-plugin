# GitNexus workflow

GitNexus используется как инструмент навигации и impact analysis, а не как источник истины о продукте.

## Перед изменением кода

При изменении существующего класса, функции или метода сначала оцени его влияние через GitNexus. Для незнакомого участка используй execution-flow/context queries вместо слепого поиска по тексту.

Если impact показывает высокий риск, остановись и пересмотри границы изменения до продолжения.

## Во время рефакторинга

Не переименовывай символы массовым find-and-replace. Для symbol-level rename используй семантический refactoring workflow GitNexus.

Изменяй минимально необходимый scope и сохраняй существующие bounded-context boundaries.

## Перед коммитом

Проверь фактический scope изменений через GitNexus `detect_changes`. Сверь результат с ожидаемым набором файлов, символов и execution flows.

Если индекс устарел, сначала обнови его. Не записывай число символов, связей или flows в документацию: эти значения относятся к состоянию конкретного индекса.

## Scope

Этот workflow не требует GitNexus для чисто текстовых изменений, если они не меняют executable symbols. Для изменений конфигурации, manifest'ов и документации достаточно обычной проверки diff и соответствующих validators.
