# Runtime source of truth

Когда в проекте расходятся текстовая документация и фактическое поведение, не исправляй runtime под документацию автоматически.

## Приоритет источников

Для текущего поведения используй исполняемый код, schemas, registries, manifests/configuration и executable tests.

Документы объясняют intent, architecture и durable policy. Они не заменяют runtime discovery.

## Derived facts

К derived facts относятся текущие количества и списки runtime-объектов, конкретные результаты тестового запуска, состояние GitNexus index, версии установленных компонентов и другие машинно выводимые свойства.

Derived facts не следует копировать в постоянные инструкции. Если такой факт нужен пользователю, получай его непосредственно из соответствующего инструмента.

## Contract changes

При изменении schema/registry/runtime registration сначала меняй executable source of truth и его tests. Затем обновляй документацию только там, где меняется устойчивое пользовательское или архитектурное понятие.

Не добавляй документальный chore только ради изменения числа.
